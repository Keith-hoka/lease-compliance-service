# CI Corpus Dump Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The corpus-gated rule and clause tests run in CI against a checked-in pg_dump of the full corpus instead of self-skipping.

**Architecture:** A refresh script pg_dumps the three corpus tables from the dev store into `tests/fixtures/corpus.dump` (measured: 992 KB, 3018 sections + 4 acts + 97 ingested_versions, pg_dump 16.14); the CI test job restores it into a second database on its existing postgres:16 service and exports `DATABASE_URL` so `settings.database_url` finds it. A CI-only guard test fails (not skips) when the corpus is unreachable, so a broken restore can never silently return the suite to green-with-skips.

**Tech Stack:** pg_dump/pg_restore custom format, GitHub Actions, existing pytest fixtures — no code changes to tests or rules.

**Spec:** `docs/superpowers/specs/2026-08-06-ci-corpus-dump-design.md`

## Global Constraints

- Corpus tables exactly: `acts`, `sections`, `ingested_versions`. No operational tables in the dump.
- Dump path exactly: `tests/fixtures/corpus.dump`. Script path exactly: `scripts/refresh-corpus-dump.sh`.
- CI corpus database name `lease_compliance`; pytest env
  `DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5433/lease_compliance`
  (the settings field `database_url` reads the `DATABASE_URL` env var).
- The dev corpus store lives in the postgres container `rental_management_app-db-1` (user `rental`, db `lease_compliance`, host port 5433).
- No change to any test file except the new guard test; no rule or app code changes.
- `llm_eval` stays opt-in — untouched.
- uv only, no emojis, ruff sequence, commit + push + CI green per task. Commit trailer: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

- [ ] **Step 1: Write the script**

`scripts/refresh-corpus-dump.sh`:

```bash
#!/usr/bin/env bash
# Refresh tests/fixtures/corpus.dump from the dev corpus store, or
# restore the committed dump into a fresh dev store with --restore.
#
# The dev store runs in the rental_management_app-db-1 postgres
# container (user rental, database lease_compliance, host port 5433).
set -euo pipefail

CONTAINER="rental_management_app-db-1"
TABLES=(-t acts -t sections -t ingested_versions)
DUMP="$(git rev-parse --show-toplevel)/tests/fixtures/corpus.dump"

if [[ "${1:-}" == "--restore" ]]; then
    docker exec -i "$CONTAINER" pg_restore -U rental -d lease_compliance \
        --clean --if-exists --no-owner --no-privileges < "$DUMP"
    echo "restored corpus from $DUMP"
else
    docker exec "$CONTAINER" pg_dump -Fc -U rental -d lease_compliance \
        "${TABLES[@]}" > "$DUMP"
    ls -lh "$DUMP"
fi
```

`chmod +x scripts/refresh-corpus-dump.sh`

### Task 2: CI restore wiring and the corpus guard test

**Files:**
- Modify: `.github/workflows/ci.yml` (test job: restore step + pytest env)
- Test: `tests/test_corpus_ci_guard.py` (new)

**Interfaces:**
- Consumes: Task 1's `tests/fixtures/corpus.dump`.
- Produces: corpus-gated tests running in CI; a guard that turns a missing corpus into a CI failure.

- [ ] **Step 1: Write the guard test**

`tests/test_corpus_ci_guard.py`:

```python
"""In CI the corpus store must be present - a broken restore fails loudly.

Locally the store may legitimately be absent, so the guard skips when
the CI environment variable (set by GitHub Actions) is missing.
"""

import os

import pytest
from sqlalchemy import select


async def test_corpus_store_available_in_ci():
    if not os.environ.get("CI"):
        pytest.skip("guard applies only in CI")
    from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

    from app.core.config import settings
    from app.models import Act

    engine = create_async_engine(settings.database_url)
    factory = async_sessionmaker(engine, expire_on_commit=False)
    async with factory() as session:
        slugs = {act.slug for act in (await session.execute(select(Act))).scalars()}
    await engine.dispose()
    assert {
        "act-2010-042",
        "sl-2019-0629",
        "residential-tenancies-act-1997",
        "residential-tenancies-regulations-2021",
    } <= slugs
```

No exception handling by design: in CI an unreachable store raises and
the test fails - that is the guard.

- [ ] **Step 3: Wire the workflow**

In `.github/workflows/ci.yml`, after the `uv sync --dev` step of the
`test` job and before the pytest step, insert:

```yaml
      - name: Restore corpus fixture
        run: |
          PGPASSWORD=postgres createdb -h localhost -p 5433 -U postgres lease_compliance
          PGPASSWORD=postgres pg_restore -h localhost -p 5433 -U postgres \
            -d lease_compliance --no-owner --no-privileges tests/fixtures/corpus.dump
```

and extend the pytest step's env:

```yaml
      - run: uv run pytest -q
        env:
          TEST_DATABASE_URL: postgresql+asyncpg://postgres:postgres@localhost:5433/lease_compliance_test
          DATABASE_URL: postgresql+asyncpg://postgres:postgres@localhost:5433/lease_compliance
```

`--no-owner --no-privileges` is required: the dump's objects are owned
by the dev role `rental`, which does not exist in CI's postgres.
ubuntu-latest ships postgresql-client 16 (the dump is pg_dump 16.14);
if the restore step fails on a client/server version mismatch, add an
`apt-get install -y postgresql-client-16` line above it and note that
in the report.
